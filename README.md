# GGB · 账号内容工作 Skill

把真实人物、业务和用户问题，推进为有依据、能讲清、能拍出的账号内容。一个入口按需处理内容策划、定位访谈、同行视频与行业研究、选题评分、脚本和审核复审，适用于不同行业的企业账号、个人 IP 与员工矩阵。

显示名称：**GGB**。调用标识：`ggb`。当前版本：`0.3.2`；配套泛话题 Skill `ip-general-topics` 为 `0.1.3`。

本仓库同时分发两个 Skill。使用 GGB 的泛话题分支时安装两者；也可单独调用 `ip-general-topics`。本次补充聊天式口播、具体句意、跨场景连接、固定结尾去重、明确不限时长及重复修改失败后的重诊规范。原 GGB 评分、研究、确认流程继续沿用。

## 安装

用支持 Agent Skills 的安装器选择自己的 Agent：

```bash
npx -y skills add sfy0923/account-content-skill --skill ggb ip-general-topics -g
```

安装到 Codex：

```bash
npx -y skills add sfy0923/account-content-skill --skill ggb ip-general-topics -g -a codex -y
```

安装到 Claude Code：

```bash
npx -y skills add sfy0923/account-content-skill --skill ggb ip-general-topics -g -a claude-code -y
```

此前安装过`account-content-workflow`的使用者，应按上面的新命令安装`ggb`，确认可用后移除旧入口，避免重复发现。显示名使用GGB；目录与调用标识按Skill格式使用小写ggb。仓库地址保持不变。

也可以将 `skills/ggb/` 与 `skills/ip-general-topics/` 分别完整放入自己 Agent 支持的 Skill 目录；入口和按需引用文件应一起保留。只使用原 GGB 分支时可仅安装 `ggb`。安装器参数见 [skills 官方说明](https://github.com/vercel-labs/skills/blob/main/README.md)，目录格式见 [Agent Skills 规范](https://agentskills.io/specification)。

## 怎么用

从当前需要的阶段开始，已有账号资料和确认结果不必重填。支持 `$ggb` 调用的 Agent 可直接使用：

```text
使用 $ggb。
本轮只做选题：根据我提供的账号资料，给3条解决方案型选题。
保留七项评分、依据、语义去重和可拍状态；不够90分如实说明。
行业与实际业务：……
人物与目标观众：……
本轮目的、原始材料、历史选题与拍摄条件：……
```

写稿时提供选题、受众、人物、材料、目的、成片总时长、拍摄条件和已有答案／方案确认进度。关键需求不清会先确认；知识题先交答案，再确认方案，之后写完整稿。审核可以只找问题，也可以要求“初审→必要修改→复审”的完整闭环。

没有支持当前任务的策划、访谈稿或录音时，GGB会先找并分析一条相关同行作品，做小型行业词图和检索记录，提炼适合当前账号的问题与方法，再回到选题或用户要求的阶段。已有足够书面材料或只改局部时不重启研究。工具按所在环境能力选用，付费数据或转写服务不是安装前提；无法取得原声、完整视频或平台原生结果时如实降级，不补造逐字稿。

```text
使用 $ggb。我暂时没有策划和访谈材料。
行业、实际业务与出镜身份：……
目标观众、内容目的与平台：……
先找一条同行分析，再给3条选题；不要直接写完整稿。
已有同行链接或文件（如有）：……
```

## 保留的方法

- 内容策划围绕一个主目标、真实人物能力、具体用户场景和可用资源。
- 选题区分故事型与解决方案型，按结论、动作或结果语义去重。
- 七项评分先给0—5分，再按 **5／4／2／3／3／2／1** 加权，满分100；90分是候选入选门槛。硬门槛、重复及授权缺口不能由高分抵扣。
- 前置研究使用题目潜力与当前落地准备度双层评价，潜力85分仅为优先研究档；正式选题仍按原七项90分复核。未知评分项不当作0分，同行的条件不计作本账号已准备齐全。
- 正式批量未指定数量时，两类各至少10条；单条或少量请求按指定数量，不凑数、不虚打高分。
- 新稿默认五段“共情痛点、冲突、框架、共鸣、解决问题”，预计成片约3分钟；用户指定结构和时长优先，说清就停。
- 跨行业写稿在策划中记录已选核心主题，正文通过具体人事、行动、对话和过程表达，不出现主题名称或换抽象标签点题；写稿与审核均检查是否漏入主题名称或同义点题，以及正文是否仍能支撑核心。
- 完整稿包含台词／配音、分段时间、画面动作、字幕和拍剪提示；未经试读／试拍只报告估算。
- 审核允许零问题和零修改，意见可以撤回，失败修改可以部分回退。
- 聊天式口播保留本人判断与理由，不用剧情替代；逐句说清人和事，去重复不删因果。指定结尾先锁定再反查前文，明确不限时长时先讲清再估时。相同问题连续两轮未解，重查完整稿和相关段落；规范更新不等于用户认可上一版稿。
- 员工矩阵等真实项目接入时，再确认角色分工、共用材料授权与跨账号去重范围。

## 工具与边界

核心流程只需 Agent 能读取 Markdown，不依赖飞书连接、指定模型或特定 MCP。涉及当前专业知识、产品或平台规则时，需要可靠来源和相应检索能力；没有则明确待核实。

可选评分计算器使用 Python 3，无第三方包：

```bash
python3 skills/ggb/scripts/score_topic.py 5 4 5 5 5 4 5 --dedup independent --other-gates passed
```

它只负责算分，不能替代事实、语义去重或授权判断。未指定完成状态时不会自动入选。分数不预测播放、过审、咨询或成交。

不要把未经授权的客户资料、个人隐私或凭证加入公开仓库。原话、人物口述、公开材料、模拟和模型判断分别记录；模拟需要明确授权与观众可辨认的标记。

## 验证与维护

结构、算分、行为和安装的实际验证范围记录在 [验证记录](docs/validation.md)。当前版本的真实客户项目验收仍需指定账号及原始材料；合成测试不当作真实业务或成片效果证据。

后续反馈先定位影响哪个决策或阶段，再做必要修改、检查回归，并在获得同步授权的范围内提交到本仓库。维护方式见 [维护说明](docs/maintenance.md)。

## 0.3.0 泛话题接入

新增可独立安装的 `ip-general-topics` 分支。GGB 负责项目事实、前置研究、用户确认和最终交付；该分支负责泛话题的选题、方案、口播写作、审核、修改与复审。从0.3.2起，本仓库在 `skills/ip-general-topics/` 同时提供完整子Skill包，无需寻找另一个仓库。宿主仍需要能够发现并读取子 Skill，或由调用方提供其安装根目录；缺少入口或必要资源时明确返回缺项，不静默改用原流程。

收到新 IP 基本信息、首次开发内容且尚未明确范围时，先询问是否看泛话题和非泛话题各1条选题，明确回复后才开始研究或生成。各一条指选题与核心观点，不授权两篇完整稿。已有明确范围、审核、局部修改和续接任务不重复询问。

泛话题完整选题默认目标为8×8＝64条，小样按明确数量执行；自然口播默认预计90至120秒，先确认方案，完整稿的纯正文与拍摄执行表分开，不强制五段或90分。上述“保留的方法”中的故事／解决方案分类、七项评分、90分门槛、两类各10条和五段3分钟默认继续用于原 GGB 分支，不覆盖泛话题。混合批次逐条保留分支、标准和版本，事实与确认状态仍分别记录。

接入方式是由执行任务的 Agent 定位、读取并执行 Skill 规则，不承诺所有宿主支持通用嵌套 API。文件安装、当前环境实际加载、构造任务、真实客户验收和实拍效果分别记录；新增入口不代表这些验证已经完成。实际完成的校验与测试以 [验证记录](docs/validation.md) 为准。
