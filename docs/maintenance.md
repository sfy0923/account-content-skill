# 维护与同步

仓库中的 `skills/account-content-workflow/` 是分发真源。安装目录是使用副本；不要只改安装副本，造成下一次安装丢失修改。

用户反馈到来时，先恢复有效要求，判断是当前项目的特例，还是会反复出现的方法缺陷。项目角色、具体收费、业务数字、客户经历和矩阵配置留在项目资料中；改变通用判断的反馈才进入 Skill。

处理一次方法修改：

1. 定位实际失败及受影响的阶段；核心方向改变先确认，已授权的普通修正直接完成。
2. 在入口或对应 reference 中做必要修改，避免重复定义同一规则。评分权重、门槛、事实边界和确认进度如需改变，说明影响。
3. 检查命名、相对引用、UI元数据和新脚本；运行可选算分器的有效及无效输入，行为变更用独立任务检查。
4. 在 `docs/validation.md` 写清实际验证范围，版本改动更新 Skill 元数据及 README。没有运行的测试不能写通过。
5. 检查工作区与暂存区，只提交明确的分发文件；不提交客户资料、测试答案、密钥、日志和本机路径。
6. 用户已授权同步时，提交并推送到对应仓库；遇到远端冲突先拉取并审阅，正常合并，不强制推送。授权范围变化或存在覆盖删除时先确认。
7. 核对远端内容和提交标识，必要时再从 GitHub 来源验证安装与资源一致性。

使用者更新安装副本可运行：

```bash
npx -y skills update account-content-workflow
```

若当前安装器无法更新该来源，按 README 安装命令重新安装，并保留自己的项目记录。仓库变更不会自动改变所有同事的已安装副本；更新后让 Agent 重新加载 Skill。

同步是任务触发的维护流程。仅有这个文件不表示已创建后台监控或自动发布任务。
