# 脚本创作

适用于真人口播、故事口播、剧情、配音加画面等形式。目标是让一条内容讲清一件值得讲的事，人物说得出口，观众听得明白，现有条件能够拍出来。

## 1. 入口与有效要求

先读取当前对话和上游交接，不要求用户重新填写已知信息。沿用最新明确要求，以及此前已确认、尚未被推翻的受众、事实、核心判断、人物口吻和表达边界。建议、假设、参考稿和审核意见不自动成为确认要求。

只执行本轮请求的阶段。创作入口需要识别以下信息，缺什么补什么，不机械发完整问卷：

- 选题或观众的问题、具体受众、本条单一主要任务。
- 行业与实际业务、账号及说话者身份、已确认经历、说话习惯和表达舒适区。
- 原始材料、本人实际做法、公开来源、真实案例与待核实项。
- 内容形式、成片总时长、人员、场地、设备、实物及可用素材。
- 已确认的结构、结尾目的、必须保留和不能出现的内容。
- 是否允许模拟，以及允许补充的具体范围。
- 当前进度：需求未清／答案待确认／答案已确认／方案待确认／方案已确认／已有稿。

新稿默认保留五段标题：**1. 共情痛点、2. 冲突、3. 框架、4. 共鸣、5. 解决问题**。默认成片总时长约 **3 分钟**，包括全部台词、动作、停顿、空镜与转场；不得把框架部分单独写成三分钟。用户指定的结构、时长和输出格式覆盖默认，只适用于其确认的范围。

最省事的创作输入是：选题＋给谁看＋谁来讲＋现有材料＋希望观众明白什么。

## 2. 缺口与材料边界

一条稿只承担一个主要任务。用普通话在内部回答：谁会想看、他遇到什么、标题答应讲什么、看完具体多明白什么、结论由什么材料支持。仅有“展示专业、提升认知、引起共鸣”时，继续明确具体内容。

关键需求或决定核心结论的事实不清楚时，先确认，不直接写完整稿。每轮通常问 3–5 个关键问题，简单任务少问；已知不重复，不为凑数追问。说明缺哪项，以及它影响哪句判断。用户暂时答不了时，整理其需要向客户了解的问题。

缺少真实客户故事不必阻断创作：已有资料足以解释，可以使用无案例的解释、对比、观察或算例。用户说“跳过、直接写”不授权编造经历、服务、收费或结果。决定性材料仍不足时，只问最关键的信息，或在用户接受的范围内交待补草稿，不能称其可直接拍摄。

材料的**性质**和**核验状态**分别记录：

| 材料性质 | 使用边界 |
| --- | --- |
| 用户或说话者口述 | 保留其提供的经历、做法和观点属性，不冒称独立核实的行业结论 |
| 已确认真实案例 | 可调整叙述顺序和口语，不改数字、动机、因果及结果 |
| 客户原话 | 准确引用；概括注明转述，不把改写放进引号冒充原话 |
| 公开资料或公开案例 | 核对来源、日期、地区、对象及条件，不改成本人亲历 |
| 假设、示意、模拟 | 仅在授权范围内使用，让观众能够辨认，不证明真实效果或发生频率 |
| AI 推断 | 标明推断，不包装成人物从业经验 |

核验状态可用：已核实并有依据／用户提供但未独立核验／材料不足以支持／尚未核实／与可靠材料矛盾。未核实不等于虚假，有来源不等于来源支持结论。

## 3. 两项分类与知识答案

分别判断答案性质与讲法，不能用其中一项代替另一项。

**答案性质：**

- **有明确知识答案**：本题可以依据资料说明原因、判断条件、费用或规则，先核实答案。
- **部分有答案**：区分通用知识与客户、商家必须确认的做法，不替其作承诺。
- **主要是经历、选择或观点**：回到事实和人物立场，不硬找统一标准答案。
- **暂时判断不清**：先查必要资料；仍影响写法时只确认那个关键问题。

“为什么、怎么选、怎么办”不自动意味着有唯一答案。这里的知识答案指足以回应本题的、有依据的解释，不意味着所有人和情境只有同一结论。

涉及品牌、型号、版本、参数、专业知识、现行政策或平台要求，优先查官方资料、原始材料和可靠专业来源。先查齐本题与目标观众有关的必要答案，不只核实开头的一点，也不扩成行业百科。网上资料不能证明人物做过什么、提供过什么服务、取得过什么成绩。无法核实时明确待核实，不声称查证或保证过审。

有明确知识答案时，先单独提交大白话答案，**暂不写脚本**：

1. 一句话说明给谁看、回答什么。
2. 列齐必要要点，逐项说清是什么、为什么相关及必要条件。
3. 区分可核实事实与规则、需要条件的专业建议、必须由客户确认的内容。
4. 将必要术语翻成外行听得懂的话，确实影响选择的细节才展开。

“完整”只指本题所需答案完整。用户看过确认后，再共同决定取舍。若缩短会让原选题答不全，说明保留、拆分或延长的取舍并确认，不能悄悄缩小标题承诺。

流程为：**答案确认 → 简短方案确认 → 完整稿**。不得将三者一次性交付替代确认。非知识型内容直接依据充分材料进入方案；已确认阶段不重复，只确认新增或改变的部分。

## 4. 选择讲法并提交方案

### 故事型

看事件是否发展和变化：有人想办成一件事，采取行动，遇到变化，作出回应，产生结果或新的难题。题目出现人物不等于故事型。

默认用第三人称自然讲述，已有确认的人称与人物表达优先。把事情讲接上：为什么行动、做了什么、哪一步改变计划、其他人怎样回应、最后如何处理。真实材料缺少的动机、对话和结局不能补成事实。

解决办法尽量由故事中的核对、选择、沟通或处理体现，避免前面少量故事、后面大篇说教。不要每条都套同一种事件顺序。

### 问题解决型

重点是原因、判断或方法。直接解释更清楚时不用强编顾客。先给本条回答，再用条件、过程、对比或必要计算支撑，不用案例代替知识答案。可以按点讲，知识点数量由答案和时长决定。

获准的一小段假设可以帮助理解，不因此把整条改成虚构故事，也不要求每条都带场景。

### 判断不清

只确认影响走向的选择，例如完整讲一件事，还是主要把问题解释清楚。两种都成立时给推荐及一句理由，等用户确认。

需求明确后，提交短方案：受众与主任务、核心回答、讲法、开头、各段推进内容、大致时间分配、需要选择的创意点、结尾方式。结尾是否引导以及引导什么要依据用户确认，不自动加关注、咨询、私信或购买。

等方案确认再写整稿。用户已确认方向并明确要求直接出稿时直接完成；改变受众、立场、主任务、结构或案例性质时，重新确认受影响的关键选择。

## 5. 五段的作用

五段方便沟通和拍摄，正文须连续推进，不写成五篇小讲解，也不在框架、共鸣和结尾重复全套答案。

| 段落 | 作用与边界 |
| --- | --- |
| 1. 共情痛点 | 从具体处境、选择或好奇进入，让观众知道想办什么、卡在哪。用具体陈述开头，不靠问候、自我介绍或无依据的恐惧 |
| 2. 冲突 | 一个现实矛盾或有依据的反常识落差，说明哪一步变化影响了谁的计划、时间、钱或选择。不编争吵、欺骗、损失或恶意 |
| 3. 框架 | 故事继续推进事件；问题解决解释原因、条件、过程或方法。术语随句解释，数字交代必要口径，不用抽象提醒填充 |
| 4. 共鸣 | 从具体处境呈现理解，不凭空读心，不喊“我理解你”，不重复答案或升华成人生道理 |
| 5. 解决问题 | 故事落在实际收尾或选择；方法给相关且有条件的下一步；判断收成可使用的结论。可很短，不必另列行动清单或营销 CTA |

没有真实痛点证据时从疑问、选择或好奇进入。五段标签不授权制造冲突、心理、万能办法。用户明确省略某段或改结构时照本条要求，不强补。

## 6. 表达与跨行业适配

### 核心主题与正文表达

在内部策划和跨阶段交接中记录本条已选核心主题的名称，多个主题分别列出。已确认的直接继承，局部修改不重开问卷。主题名称可以出现在策划、审核和文件名中，不能进入口播、配音、人物对白、正文补充字幕或结尾字卡。

正文用具体人物、事情、行动、对话、选择和过程承载核心，不能中途或结尾直呼主题，也不能换成另一个抽象同义标签直接点题。按已选主题的完整词组检查，不拆成单个汉字，不连带禁止未选为核心主题的行业、产品等名称；同义点题按整句语义判断，不能扩成同义词黑名单。

用户指定必须逐字保留的引用若与该规则冲突，指出具体引语、所含主题名称或点题表达和冲突，不擅改引语；只确认该处如何处理，不重问无关需求。

### 自然表达与事实边界

让人物像当面解释事情一样说话，保留必要的主语、对象、原因和动作。一句话一个主要意思，允许有作用的重复、自然停顿和态度，不追求句式整齐。口语改写只改表达，不偷换人物立场、价格含义、因果或事实强度。

- 抽象词必须落到本题的具体人、物、事、动作、条件和后果，不靠“综合考虑、具体分析”代替答案。
- 术语和参数只有影响理解或选择时进入口播，并说明白；字幕不能替代本来缺失的解释。
- 避免报告套话、广告腔、工整排比、口号收尾、机械对照句、用比喻代替解释。
- 知识型可以自然编号，不把整稿念成文件；自问自答默认最多一处，不连续把解释推给观众。
- 口播正文不使用分号，不写小说式动作与镜头心理；剧情动作放入可执行的拍摄说明。
- 样稿用于学习节奏、词汇和态度，不复制未确认事实与错误判断。没有样稿不冒称完全复现本人。

### 聊天式口播与连续修改

已确认聊天式口播时，以IP对观众说话为主，保留其疑问、判断、理由与取舍。例子用于说明，不用连续角色对白、动作或纯故事复述取代本人表达。去说教不能靠删掉思考或擅改成剧情；方法类任务仍保留必要操作指导，不把建议句一概当成说教。

普通词也要检查整句含义：谁对谁做了什么、改变哪个选择，前后主语与条件是否清楚。需要再解释一句才懂，就用具体解释修原句，不能只把书面词换成“这样、处理、用到身上”。按语义判断，不建词语黑名单。

跨场景展开要写清前后人物、处境以及旧经验为何与当前选择有关；只说“学会了”或再讲一次原例都不能补齐关系。不将一次经历写成必然改变。例子已讲清时直接往下，不再补一段同义解释或总结道理。

用户锁定结尾或某句时，先保留原文，再反查前文同一行动或判断是否已经说完。改其余部分的重复，保留必要理由与连接；不能删完接不上，也不能用另一句道理填空。后来明确修改锁定句时，只解除对应范围。去重比较整篇的实际内容，不只数相同词语。

换行业或客户，重新读取说话者、受众、业务关系、具体产品或服务、收费交付、资质与承诺边界。不得只替换名词，沿用旧客户的城市、从业年限、客户数、服务、比例、期限、业务或授权。

仅针对本题实际涉及的广告、隐私、医疗、金融、法律、教育等内容核验，不机械塞入无关清单。不点名无证据贬低同行，不把情绪判断写成法律结论，不保证效果、收益、平台通过或成交。

## 7. 模拟与情节补全

只有明确允许模拟时补设定，范围不清先确认；新客户不继承旧授权。出镜人认可合理不证明真实发生。

有模拟或情节补全时，在正文前单独、明显标注，不盖住五段标题：

> 情节说明：本条为【模拟示例／含情节补全的故事】。已确认部分为【有则填写】，假设或补全范围为【具体范围】；假设或补全部分不代表真实发生。拍摄时须在相应台词或画面保留“假设／情景示意”提示；如要按真实经历讲述，先替换为已确认材料。

说明须与实际呈现一致。稿外备注不代替观众可见标记，后文也不能变回真实见证。模拟数字只解释逻辑，不冒充现行报价、统计或实际效果；模拟结果不构成照做必成功的承诺。

## 8. 时长、检查与完整稿交付

按成片总时长分配台词和视听安排。说明采用的语速假设及合理区间，给动作、停顿、空镜和转场留时间；并行口播与画面不重复累加。文字通读、字数估算与真人试读分别记录，没有实际试读或试拍不称实测。

明显超时先删重复和无作用内容，不能只标上目标分钟数。若删减会损失必要答案或条件，确认保留、拆分或延长的选择；不为凑够默认时长加话。

用户明确不限时长时，停止按默认三分钟或对应字数压缩，先讲清再估时，不删必要理由或反复申请延长；这不等于需要把稿件写长。

交付前内部检查两遍：

1. **内容成立**：标题承诺兑现、主判断有依据、知识要点齐全、事件因果接上、数字对象清楚、没有新增未确认的业务或结果。按上述正文范围逐项检查已选核心主题：既没有主题名称或换抽象标签点题，去掉点题词后也仍有具体情节或解释支撑核心，不能只剩与主题无关的空情节。
2. **人物能说且能拍**：连起来检查主语、指代、因果、节奏、重复和口吻，核对人员、场地、设备、表演能力和时长负荷。

完整稿默认格式：

```text
选题：
讲法：故事型／问题解决型；一句话说明
情节说明：仅在有模拟或补全时提供

1. 共情痛点
可直接朗读的正文
2. 冲突
可直接朗读的正文
3. 框架
可直接朗读的正文
4. 共鸣
可直接朗读的正文
5. 解决问题
可直接朗读的正文

拍摄执行说明：各段时间、画面／动作、字幕、必要声音与剪辑提示
预计成片总时长：估算区间、语速假设和未实测说明
待确认：仅列影响拍摄或结论的真实缺口，无则省略
资料来源：有必要时在正文外简要列出
```

真人口播可统一交代固定机位、自然停顿和必要字幕，不为每句强编镜头。剧情与配音加画面须对应给出画面、动作、字幕和声音安排。画面不能悄悄承担未解释的关键事实。

用户明确只要逐字稿或局部时按其格式交付。决定性缺口仍须先处理，不藏到文末并同时宣称可直接拍。批量稿先核对数量，分别给全；内部分析、句式计数、逐条自查和长篇核验过程不默认输出。
