# 选题模块

仅在生成、筛选、修改或复核选题时读取。选题通过后交接到脚本阶段，不自动生成完整脚本。沿用已有账号定位、事实和确认进度，不重新询问已经明确的信息。

## 1. 确定本轮范围与材料

识别本轮是单条、少量校准、正式批量还是已有选题复核。用户指定数量、类型或只改部分时，按指定范围工作。

- 正式批量未指定数量时，默认解决方案型至少 10 条、故事型至少 10 条，共至少 20 条；最终合格题须达到 90 分且通过硬门槛。
- 少量或单条请求覆盖批量默认，不扩成 20 条；不因数量少而降低事实、去重或评分标准。
- 首次校准可先交 5—10 条，确认语言与方向后再扩展。已经确认过的表达不重复审批；用户明确授权按现有标准直接完成时继续。
- 正式批次可从 30—50 条内部候选开始。合格数不足时补新方向或材料，报告实际数量和缺口，不复制旧题、编故事或虚打高分凑数。
- 题源不足、业务事实不足和缺少真实故事是不同问题。足以解释问题的材料可以支持无案例选题；关键结论无依据时先追问。没有真实故事且未获准示意时，不擅自生成演绎故事凑配额。

从已有对话和项目材料提取以下必要信息；只有缺口会改变本轮判断时才问：

| 信息 | 提取内容 |
| --- | --- |
| 账号与业务 | 行业、实际产品或服务、主体身份、已确认定位、本人参与到哪一步、一个主目标 |
| 受众与题源 | 具体观众、处境和阶段，原话、评论、搜索词、访谈或工作节点；没有原话记“暂无” |
| 事实与授权 | 可公开材料、来源和核验状态、人物口述、待核实项、模拟授权范围、不能公开的内容 |
| 工作与制作 | 实际流程、人员、场地、道具、表达样本、预计成片时长及限制 |
| 历史与本轮 | 已拍、待拍、被否、待改的选题及原因，避开方向、数量、类型、资料更新时间 |

以“需求出现 → 接触和了解 → 判断和选择 → 实际执行 → 出现意外或分歧 → 结果与后续”整理真实流程。每阶段记录谁来、为什么来、原话、主体做了什么、判断依据、容易出的问题、结果和可公开材料。没有的阶段不硬填；只有实际具有销售性质时才补售后、复购、转介绍。

矩阵账号的分工、共用素材授权和跨账号去重范围，在实际接入矩阵任务时再确认。未提供这些配置时，不假定不同员工可以重复同一核心，也不宣称已完成矩阵分工设计。

## 2. 从问题池到唯一核心

按以下顺序处理每条候选：

1. 保留原始题源及来源位置，整理成“具体的人或角色—场景中的事—痛点或选择—结果”的问题池。运营者提出的假设须与真实用户原话分开。
2. 确定主受众及他当前处在哪一步，再记可能感兴趣的次受众；没有明确次受众写“暂无”，不能用“所有人”扩大范围。
3. 写观众看完只记住的一个结论、动作、判断或事件结果，再写完整具体内容、观看理由和必要条件。
4. 判断主要价值、经验依据和答案性质，各轴分别标注。
5. 最后提炼标题，再做大白话检查、语义去重、硬门槛和评分。

找入口时可检查钱、时间、风险、信任口碑、合规安全、家庭身份六类痛点，以及生活问题、工作过程、行业观点、主体日常和自然反差。它们是发散方向，不是必须凑齐的配额。先前批次的数量组合不能强套到本轮。

先写完整核心，再缩标题。标题不设硬字数上限；短而清楚就短，缺主语、场景或因果就补足。不要把整条口播稿塞进标题。主语按实际场景选择，不固定用“老板”或“客户”。默认可用陈述句，但不为回避问号制造别扭表达。所谓“内幕”必须有可说明的依据，不能把好奇角度当编造许可。

## 3. 分类轴分别处理

| 分类轴 | 标记与判断 |
| --- | --- |
| 主要价值 | 解决方案型／故事型，每条选一个，按整条主要价值判断 |
| 子标签 | 解决方案型可用问题答疑、行业科普、实操判断；故事型可用真实记录、人物口述、行业常见场景、示意场景、剧情演绎 |
| 经验依据 | E：能说明亲历步骤、判断依据、例外和结果；R：无足够亲历依据，需研究；M：混合／待核实，有相邻经验、零散案例或部分亲历。只讲已确认部分，经验状态不能替代来源与核验状态 |
| 主要角度 | 过程／结果，说明本题关注什么，不替代主要价值 |
| 表达风格 | 落地科普、猎奇反差或项目已确认风格，说明怎么讲 |
| 拍摄形式 | 口播、对话、剧情、日常记录、配音加画面等，按实际资源确定 |
| 材料状态 | 已确认事实、人物口述未独立核验、待核实、示意、演绎等，保留各自属性 |
| 答案性质 | 有明确标准答案／部分有标准答案／不标注，按下一节判断 |

故事型不等于剧情拍摄，解决方案型也可以用故事开场。开头出现人物或事件，不能单独决定主类型。若正文主要教一个判断或动作，应归解决方案型；事件发展、选择和变化本身提供主要价值时，归故事型。判断不清且影响方向时，只问这个关键选择。

经验依据检查“我做了什么—按什么判断—出现什么例外—结果怎样”：能够说明才用 E，只能说明部分用 M，缺亲历依据用 R。E 可以讲个人流程，不能冒充普遍规律；R 以整理、解释或研究身份讲；M 的其余内容标待核实。状态变化时同步检查标题、台词、画面证据及第一人称范围。

### 解决方案型

回答普通人正在遇到的一个问题，提供可执行的判断、顺序或动作。先说清谁、什么情况、担心什么、具体看什么或做什么、为何这样做、适用条件、可能后果、事实依据与待核实项。不能只写“要注意”“先确认”“有门道”，也不把有条件的建议写成保证结果。

### 故事型

说清一个具体的人带着什么任务或问题、原本想得到什么、做了什么、遇到什么反应或变化、最后发生什么或面临什么选择，以及观众能看懂的唯一结论。冲突来自行动后的阻碍或不同选择，不靠强加争执或惊人口号。

素材须区分真实记录、已获授权口述、常见场景概括、示意和演绎。缺真实素材时，只能在获准的范围内做示意或演绎，并明确标注；不能虚构人物、成交、价格、反馈和结果冒充主体亲历。具体物品帮助理解，不证明主体接触过该物品。“行业常见”也需要依据，不能用于掩盖自拟情节。

## 4. 标准答案标签

选题者根据材料主动判断，不要求项目方先替选题者给出所有答案。标准答案是附加标注，不是第三种主类型，也不是专业程度或评分加分项。

- **有明确标准答案：** 在说明适用条件后，可给出明确、可核实的做法、判断依据或检查清单。写清它回答哪个问题，不把“应该核对哪些事”偷换成“所有商家给出同一结果”。
- **部分有标准答案：** 明确哪些能确定，哪些仍取决于商品、商家、地区、合同或个人情况；不把具体店铺承诺写成通用规则。
- **不标注：** 主要是偏好、个别经历或主观判断，或缺可靠依据、关键条件待核实。不能把“问一问”“看情况”冒充答案。

只有确实适用时展示标签及答案范围。故事若主要教一套明确做法，应按主要价值改判为解决方案型。有无标准答案不增加或扣减额外分数，也不降低事实和去重门槛。

涉及会变化的政策、价格、产品或行业规则时，先核实当前可靠来源及时间、地区、范围。没有检索能力或来源不足时标明未核验，不宣称标签已经成立。进入脚本后，有明确知识答案的题目须先交完整大白话答案并沿用真实确认进度，不能用故事包装代替知识答案。

## 5. 大白话检查

先对标题、唯一核心和具体内容逐条检查：

1. 无行业背景的人能否知道谁、在什么情况下、遇到什么事？
2. 能否知道他为什么在意，会失去什么、耽误什么或面临什么选择？
3. 解决方案型是否有具体、适用且能执行的判断或动作？故事型是否有事件发展，而不只是物品简介？
4. 标题与核心是否同一件事，是否偷偷塞入两个主问题，正文能否兑现标题？
5. 内部术语能否直接换成日常说法，而不是移到字幕或让观众自行理解？

需要读者猜测的先改，不直接用高分通过。这里只能进行文本自查；没有实际外行试读，就写“大白话文本自查”，不能声称已完成真实陌生人朗读测试。

## 6. 语义去重与历史范围

维护项目历史选题索引，纳入已拍、待拍、被否、待改及本轮候选。每条记录核心内容 ID、主类型、观众记住的结论／动作／结果、角色与场景、关键原因或动作、痛点与后果、最近似题及实质区别。已有 ID 沿用，新增 ID 在项目内持续编号。

遮住标题比较核心：观众能否用同一句话复述两条？仅换行业、物品、人物、地点、标题句式，或把规则改写成故事，不形成新核心。

- **独立：** 判断、动作或结果明显不同，重复扣分为 0。
- **相邻：** 同一问题的邻近环节，先改至少一个真正影响结论的变量；未改好扣 5 分，并且不得入选。改好后重新判断关系与评分，不能仅把扣分删掉。
- **重复：** 核心结论相同，扣 10 分并 Pass；保留证据更足、痛点更强的一条。与历史核心相同直接 Pass，高分不能保留重复题。

解决方案组与故事组也互相去重，不在故事里换个人名重讲同一个办法。检查本轮是否过度集中于同一损失、同一流程节点或同一种受众，必要时补新方向。

历史索引未提供时，可以完成本批去重，但必须报告“跨批次去重未验证”；不能把未知历史写成没有重复。此时最近似历史题记“历史未提供”，仅说明本批入选判断，并保留待历史核对状态。未覆盖的其他账号同理，不宣称全矩阵无重复。

## 7. 七项评分与入选

先检查事实、口语、痛点、核心和去重硬门槛，再评分。被否候选也保留可解释的分数及原因，硬门槛失败不能由高分抵扣。

每项给 0—5 分，再乘相应权重：

| 评分项 | 权重 | 分项依据 |
| --- | ---: | --- |
| 痛点与后果 | ×5 | 具体观众真正遇到的困难、选择及不处理的代价 |
| 场景具体、容易代入 | ×4 | 清楚的人、触发时刻、动作、对象和处境 |
| 观看理由与反差 | ×2 | 为什么值得看，自然差异或好奇点，正文能否解释 |
| 事实依据／演绎边界 | ×3 | 来源、适用范围、核验属性，示意或演绎授权与标记 |
| IP 匹配与商业价值 | ×3 | 主体实际能力、适合表达的范围及对账号主目标的作用 |
| 可拍性与持续性 | ×2 | 人员、场地、道具、时长和素材能否承接，以及可持续的方向 |
| 核心清晰度与大白话 | ×1 | 一个可复述的结论，完整且自然的日常表达 |

**基础总分＝七项原始分分别乘权重后相加，满分 100。最终分＝基础总分－重复扣分。** 权重和为 20，每项满分 5；不得直接把七项原始分相加当百分制，不另加标准答案奖励分。

需要避免算术遗漏且环境有 Python 3 时，可以使用 [评分计算器](../scripts/score_topic.py)。参数依次为痛点、场景、观看理由、依据、账号匹配、可拍性、清晰度。例如在确已完成其他硬门槛与所提供范围的去重后，运行 `python3 scripts/score_topic.py 5 4 5 5 5 4 5 --dedup independent --other-gates passed`。从 Skill 根目录运行；默认未确认状态不会自动入选。计算器只做加权和门槛计算，不负责判事实、语义、授权或历史完整性，也不确认生产就绪。没有 Python 时按同一公式计算，不将脚本作为核心能力依赖。

### 评分锚点

以下锚点用于校准编辑判断，不是经过统计验证的效果模型。逐项对照具体材料评分，不能因为其他项好就抬高本项，也不能为接近 90 分倒推分数。

| 原始分 | 通用判断 |
| --- | --- |
| 0 | 本项缺失，或存在直接违背本项的内容 |
| 1 | 只有抽象声称，无法指出支持它的具体内容 |
| 2 | 有部分内容，但主要对象、依据或关系仍不清楚 |
| 3 | 基本能理解，有一定支持，但仍有明显缺口或表达负担 |
| 4 | 具体、清楚，有可定位依据，基本满足本项；剩余限制已如实说明 |
| 5 | 在本轮材料与范围内，本项充分成立、必要条件齐全、表达自然，无需读者补关键意思 |

给 4 或 5 分时还须满足该项的具体要求：

| 评分项 | 4 分需体现 | 5 分还需体现 |
| --- | --- | --- |
| 痛点与后果 | 明确谁为何在意、代价或选择是什么 | 触发处境与代价充分相连，无需夸张后果制造重要性 |
| 场景具体、容易代入 | 角色、对象、时刻或条件、关键动作清楚 | 场景足以支撑判断或事件变化，无关细节不遮挡主线 |
| 观看理由与反差 | 有具体收益、好奇或选择，正文能兑现 | 入口与核心紧密相连，差异自然，无须虚假悬念撑场 |
| 事实依据／演绎边界 | 核心已有足够依据，材料属性与限制清楚 | 所用必要事实与条件可追溯；演绎在授权范围内且明确标记，不冒充见证 |
| IP 匹配与商业价值 | 主体有讲题依据，内容服务一个已确认主目标 | 主体的实际判断或表达优势可见，内容方向可持续，未捏造资历或成绩 |
| 可拍性与持续性 | 主要制作资源可用，仍待确认的执行项明确 | 所需人员、素材和时间条件齐全，延展方向具体且不靠重复核心 |
| 核心清晰度与大白话 | 能复述一个核心，主语、因果及条件基本完整 | 普通表达一遍即清楚，标题和内容一致，没有术语替代解释或绕句 |

人物口述不自动获得独立核验分；需要核验的行业定论不能仅靠人物自述。明确授权、边界清楚的演绎可以按其解释任务评分，不因“虚构”自动扣分，也不能作为真实效果证据加分。

### 硬门槛

- 标题及一句话核心让普通人能理解；核心清晰度与大白话至少 4／5。
- 痛点与后果至少 4／5，观看理由与反差至少 3／5；不靠冷门对象或猎奇细节撑分。
- 一个可兑现核心：解决方案型有具体判断或动作，故事型有事件变化。
- 事实来源和演绎标记清楚，不编经历、成绩、客户反馈、行业规则或平台效果；不越过公开授权范围。
- 与已提供历史及本批无相同核心，主体实际业务和主要制作能力能承接。历史缺失单列未验证，不能声称该范围已通过。

### 结果与生产状态

| 最终分与门槛 | 编辑结果 |
| --- | --- |
| 90—100，硬门槛通过 | 入选；历史未提供时限定为本批判断，跨批次仍待核对 |
| 80—89 | 修改后再审，说明改哪句或补什么，再重新评分 |
| 70—79 | 保留方向，不进最终，需换角度或补真实资料 |
| 0—69 | Pass，保存淘汰理由 |
| 重复、相邻未改好或关键硬门槛失败 | 不入选，无论分数多高；事实或授权缺口具体列出 |

编辑入选与生产准备分别记录。核心已成立、硬门槛通过，但仍有不影响核心的执行资料或画面安排待补时，可以保留入选方向，生产状态仍标“待补”，不能称已经可拍。决定核心结论的事实、必要授权或主要拍摄能力缺失时，不得把它计作正式合格题；先保留待补候选并明确缺口。状态不能只靠达到 90 分自动升级。

90 分仅表示内部编辑优先级，是本轮材料和评分者的判断，不预测播放量、平台通过、咨询、成交或客户满意度。未实测的时长只写预计。

每个候选，包括 Pass 题，记录七项原始分、加权分、各项具体依据、重复扣分、最近似题及实质区别、待改句子或待补资料、基础总分、最终分、编辑结果、生产状态。依据要指出具体的人、事、后果或材料，不能只写“很有共鸣”“感觉一般”。

## 8. 交付选题卡与批次结果

按本轮数量给完整选题卡。标题旁直接显示最终分和结果，受众、答案范围和核验限制放在卡片中，不为塞进标题写出别扭句子。

```markdown
### 【主类型｜子标签｜表达风格】标题｜最终分：分数｜结果：编辑结果

- 主受众：最需要看的人、当前阶段与具体处境。
- 次受众：可能感兴趣的人；没有明确对象写“暂无”。
- 核心内容 ID：项目内持续编号。
- 普通人一句话：谁遇到什么事，这条到底讲清什么？
- 唯一核心：看完记住的一个结论、动作、判断或结果。
- 具体内容：解决方案写具体做法及理由；故事写开始、变化与结果。
- 观看理由与痛点：为什么愿意听，在损失、担心或纠结什么？
- 与最近似题的实质区别：比较核心；缺历史明确写“历史未提供”。
- 依据与限制：来源、材料类型、核验状态、适用条件、授权、演绎标记。
- 口播入口：哪句话、动作或场景适合先讲？
- 脚本主问题：后续只围绕的一个问题或冲突。
- 拍摄形式与预计成片时长：按本项目条件。
- 生产状态：可进入脚本／待补事实／待授权／待确认拍摄条件。
- 历史核对状态：已核对的范围；未覆盖的范围。
```

确有标准答案时，在卡片中增加“标准答案标签”与“具体答案范围”，分别写能确定什么、哪些要实际确认；不适用时不展示这两行。详细七项评分及理由放在策划记录，不塞入口播台词。

批量交付包括：项目摘要；解决方案型与故事型入选卡；实际合格数量；缺口及下一轮需要补的资料；本批和历史去重范围；需保留的内部候选与 Pass 记录。用户只要某一部分时按指定交付，其余必要判断保留在工作记录。没有文件写入权限或未要求保存时，不声称已更新历史索引，提供可追加的记录。

## 9. 交接到脚本

选题通过不等于直接写整稿。交接所选题的主受众、唯一核心、主要价值、答案性质与范围、来源及核验状态、授权、开头入口、真实冲突、生产缺口、时长、拍摄条件及确认进度。

确认这条是给办法还是讲事，哪些事实能公开，结尾是否需要引导以及引导什么。有知识答案时核对最终回答的正是标签所指问题，并分清确定部分和条件变化部分。行业敏感内容与最新规则按可靠来源和适用范围核验，不作保证。

进入脚本后沿用已完成的确认，不重复审批，不将选题分数、去重术语或内部判断写进口播。材料不足以支撑关键结论时先问，不用漂亮标题掩盖答案缺口。
