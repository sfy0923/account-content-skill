# 内容策划、定位与真实访谈

本模块处理账号底盘、人物定位、题源资料和经验范围。已有定位的项目直接沿用，只补本次任务影响判断的缺口；不要因为进入新一轮选题而重新做人设。通用事实边界、方案确认和修改规则按主 Skill 执行。

## 1. 先判断从哪一步开始

| 当前材料 | 从哪里开始 | 本阶段交付 |
| --- | --- | --- |
| 新账号，目标、主体或业务不清楚 | 策划与资料收集 | 项目目标、账号底盘、关键缺口 |
| 已有底盘，但人物能力或表达边界不清楚 | 定位检查与访谈 | 定位依据、原话、能力与表达边界 |
| 缺可用策划、访谈稿或录音，但行业与账号身份已知，需要内容方向 | 先按[同行研究](research.md)补外部题源，再继续本阶段 | 代表作品、研究依据、迁移方法及本人的待确认项 |
| 已有定位、访谈和真实题源 | 资料整理与经验判断 | 可交给选题模块的资料包 |
| 只补一条题或改一条内容 | 检查本题所需字段 | 本题新增信息与待确认项 |
| 业务、目标用户或账号职责发生变化 | 检查发生变化的部分 | 更新后的底盘及变更原因 |

先整理已知信息、来源和缺口。已经确认的信息不重复询问，也不把建议写成客户已经确认的决定。当前任务无法由已有材料判断时，才追问。

材料是否不足以当前任务为准：已有足够书面访谈时不因缺录音重做研究；资料齐全或只改局部时不重复找同行。同行研究能补问题与表达方法，不能补成已访谈、已确认业务或本人亲历。

## 2. 策划：明确这一阶段要完成什么

围绕以下八项检查资料，不把它们机械地一次全问完：

1. 服务对象：个人 IP、企业账号、员工矩阵，还是具体项目？
2. 当前目的：建立认知、答疑、筛选用户、获客、转化、售后或记录过程？
3. 产品或服务：实际提供什么，能解决哪类问题？
4. 账号主体：谁讲，真实参与过哪些流程？
5. 目标用户：谁处在哪一步，遇到什么具体问题？
6. 制作资源：人员、场地、设备、素材、案例、资料和时间有哪些？
7. 公开边界：能公开什么，不能公开什么，哪些需要授权或专业核验？
8. 成功标准：本轮观察理解程度、评论质量、收藏、咨询、预约、成交，还是一次内容测试？

每阶段只保留一个主目标，其余目标列为次要观察项。不要自行给客户增加转化目标，也不要默认加关注、购买或私信引导。

策划输出：

- 项目范围、一个主目标和观察标准。
- 账号底盘与当前定位状态。
- 准备持续输出的 2—4 类问题，作为内容支柱。
- 可用资源、拍摄形式、时间与限制。
- 需要访谈、补证或先测试的事项。

## 3. 账号底盘的最小字段

| 字段 | 需要记录什么 |
| --- | --- |
| 账号／项目与主体 | 是谁的账号，由谁表达；企业账号也要明确本题的讲述身份 |
| 真实角色与经历范围 | 做过什么、没做过什么、参与到哪一步 |
| 可公开依据 | 作品、流程、资质、公开资料、授权案例或访谈记录及来源 |
| 说话习惯 | 常用词、语速、句子长短、举例方式 |
| 表达舒适区 | 自然能讲什么，不愿讲什么；不适合夸张、煽情、专家腔等哪些口吻 |
| 产品／服务和一个主目标 | 当前业务与这一阶段内容要服务的目标 |
| 核心用户 | 身份、阶段、处境与场景 |
| 希望形成的认识 | 用户以后会怎样描述这个账号或人物 |
| 可承接动作 | 已确认的评论、资料、预约、到店等动作；无承接则写“无” |
| 不可承诺与不可公开内容 | 结果承诺、隐私、客户信息、合同、内部数据等具体边界 |
| 制作条件 | 内容形式、人员、场地、设备、道具和预计成片总时长 |

未知字段标待确认，不用常见行业做法填成客户实际情况。没有真人出镜的账号，仍需要明确配音、字幕或资料说明凭什么讲，不强行增加老板人设。

## 4. 定位：有依据地回答谁、为谁、凭什么、解决什么

用四项相互检查：人物真实能力、目标用户问题、商业价值、表达边界。

可整理成定位句：

> 【人物／账号主体】以【有依据的角色】的视角，帮助【具体用户】在【具体场景或流程节点】解决【一类主要问题】，通过【内容方法或服务方式】获得【可观察的判断、动作或下一步】。

定位句是讨论稿，需要项目方确认。检查它是否具体到人群、场景和问题，是否在主体真实能力范围内，是否服务当前目标。不要只写“专业、靠谱、接地气”，也不要把定位写成保证结果。

可以从一条候选内容反向检查定位：这条内容体现什么身份，用户为什么需要听，商业连接是否自然。若内容只能靠夸大经历、虚构身份或强行制造冲突成立，回到事实和定位调整。

同时记录不做的范围：不参与的流程、不具备依据的判断、不愿公开的内容、不适合的形式，以及无法服务当前用户和目标的长期方向。

## 5. 真实访谈：先问事情，再判断人物

### 访谈怎么进行

任务信息收集时，每轮问 3—5 个影响当前判断的关键问题；简单任务只问必要项。面对面深访或逐问访谈时，围绕一个具体事件提出一个开放问题，等回答后再追问，不把多层问题塞进同一句话。

先记录原话，再归类。回答太空时，沿着时间、地点、人物、动作、判断、例外和结果追问。访谈提纲是待执行的工具；未取得实际回答时，不写成已经访谈、已经核实。

### 过去、现在、未来

| 方向 | 可用的问题 | 想获得的资料 |
| --- | --- | --- |
| 过去 | 最近一次有代表性的事情是什么时候？当时谁在场，你做了什么？ | 具体事件、亲历动作和可核验范围 |
| 过去 | 为什么这样判断？考虑过什么别的选择？哪里没达到预期？ | 判断依据、代价、例外和变化 |
| 现在 | 现在主要做什么，通常参与完整流程的哪一段？ | 实际业务和经验边界 |
| 现在 | 哪些事能独立判断，哪些要交给其他专业人员？ | 能力范围与协作边界 |
| 现在 | 哪段事情讲起来最自然？哪些内容不愿公开？ | 语言习惯、表达意愿和隐私边界 |
| 未来 | 希望影响哪类人，他们看完后能做什么判断或动作？ | 用户、目标和内容用途 |
| 未来 | 什么问题能长期讲？不希望账号变成什么样？ | 持续方向与拒绝的定位 |

不要求每次照表问完。人物说“很多、都满意、很专业”时，追问最近一次具体发生了什么，不直接把抽象评价写成定位证据。

### 从业务流程找真实材料

沿着六个阶段整理：需求出现 → 接触和了解 → 判断和选择 → 实际执行 → 意外或分歧 → 结果与后续。

每阶段记录：接触了谁、为什么来、对方原话、主体做了什么、依据什么判断、哪里容易出问题、结果怎样、有哪些可公开材料。销售性质确认后，再问售后、复购、转介绍；不存在或尚未确认的阶段不硬填。

### 访谈资料的交付

至少分开保存人物原话、已确认事实、人物经验判断、信息缺口和表达边界。每条材料保留来源位置与相关时间，原稿不被整理稿覆盖。对人物性格、优势和适合形式的判断注明是初步编辑判断，等待人物或项目方确认。

## 6. 每条题单独判断 E／R／M

经验状态属于本题，不给一个账号永久贴标签。

| 状态 | 判断依据 | 接下来怎么做 |
| --- | --- | --- |
| E：有经验 | 能说明亲历步骤、判断依据、例外和结果 | 从真实流程的一个节点拆高频误区、关键判断、隐性成本或例外；个人流程不自动成为普遍规律 |
| R：无经验研究型 | 缺少足够亲历依据，需要资料、搜索、访谈或体验 | 先研究用户原话、具体场景和风险，再回可靠来源或专业人士核验；以整理者、解释者或研究者身份表达 |
| M：混合／待核实 | 有相邻经验、零散案例或部分亲历 | 分开已确认部分和待核实部分，补足关键资料后再决定表达范围 |

核心判断：能否说清“我做了什么—按什么判断—有什么例外—结果怎样”？只回答一部分进入 M，没有亲历依据进入 R，不替人物补经历来进入 E。

R 路径依次整理用户反复提出的问题、具体用户和场景、要做的决定、概念和反例、待查问题、核验来源。工具或浏览能力不可用时，交付研究问题和待核验清单；已有知识只能标未核验，不声称已经查到当前规则。

经验状态变化时，同步检查标题、第一人称台词、画面证据和身份表述。把用户眼前动作提升到流程或判断标准，只能在人物确实有依据的范围内进行。

## 7. 缺口提问：只问会改变下一步的事

先区分三类缺口：

- **当前必须确认**：会改变主目标、主体身份、核心用户、经验范围、公开边界或本次交付；先问再做依赖它的部分。
- **可以继续整理**：缺少次要例子、补充画面或非关键细节；保留待补项，继续独立工作。
- **后续阶段确认**：不影响当前判断的发布、矩阵协作或制作细节；进入实际阶段再问。

每个问题写清缺什么、影响什么、希望对方提供什么。优先索取原话、具体事件、已有资料或明确决定，不要求用户替选题者完成研究，也不把建议自动升级成要求。

## 8. 员工矩阵：接到实际项目再配置

不要在制作 Skill、普通单账号任务或每轮选题前询问一遍矩阵设置。实际接到员工矩阵项目时，再按任务需要确认：

1. 企业共同目标与每个账号的职责、受众有什么关系？
2. 每位员工真实参与哪些流程，哪些问题适合由谁讲？
3. 哪些资料能共用，谁确认事实、授权和发布，哪些内容限指定账号使用？
4. 历史题按哪个项目或账号收集；跨账号相同核心是否允许，允许的具体用途是什么？
5. 各账号实际人员、时间、场地和表达能力有什么限制？

已有配置直接沿用，仅问变化或缺口。配置未明确时可整理已有资料与单账号事实，不自行分配员工人设、宣布团队已配置完成或声称跨账号去重已经通过。

## 9. 交给选题模块的资料包

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| 策划 | 当前目标、业务、资源和边界 | 项目范围、主目标、观察项、内容支柱 |
| 定位检查 | 策划结果、真实角色、用户问题和依据 | 已确认定位或待确认定位稿、能力与表达边界 |
| 访谈／资料整理 | 原始资料、具体事件与回答 | 原话、事实、经验判断、缺口和来源 |
| 题源准备 | 用户原话、工作流程和历史选题 | 人—事—痛点—结果问题池、历史索引状态 |
| 经验判断 | 本题亲历范围、依据和缺口 | E／R／M 状态、可讲范围、研究或补证任务 |

交接时同时附上拍摄条件、预计成片总时长、不可公开内容、待确认问题和已有矩阵配置（若适用）。没有题源或历史资料时如实标明缺失，不声称已经完成真实用户验证或跨批次去重。

后续选题继续围绕一个具体用户、一个场景和一个主问题，区分主次受众、内容主类型和过程／结果主角度，再按选题模块完成核心内容、标题、筛选与交付。
